## Summary

`is_first_block_after_epoch_checkpoint` detects the first block of each epoch after epoch 0. These blocks (heights 33, 65, 97, ...) receive the epoch-opening bonus reward (EPOCH_FIRST_BLOCK_BONUS).

## Specification

```rust
/// Returns true if this height is the first block after an epoch checkpoint.
/// True at h=33, 65, 97, ... (first block of each epoch after epoch 0).
pub fn is_first_block_after_epoch_checkpoint(height: u64) -> bool {
    height > 1 && (height - 1) % BLOCKS_PER_EPOCH == 0
}
```

## Acceptance Criteria

- [ ] Returns false for height 1 (genesis is not "after" a checkpoint)
- [ ] Returns false for height 2 (not a first-after-checkpoint block)
- [ ] Returns false for height 32 (this is the checkpoint itself, not the block after)
- [ ] Returns true for height 33 (first block of epoch 1)
- [ ] Returns false for height 34
- [ ] Returns true for height 65 (first block of epoch 2)
- [ ] Returns true for height 97 (first block of epoch 3)
- [ ] The formula h > 1 && (h - 1) % BLOCKS_PER_EPOCH == 0 is used

## Implementation Notes

- This function is used by total_block_reward() (REW-002) to determine when the epoch-opening bonus applies
- Height 1 returns false because the genesis block does not follow a previous epoch's checkpoint
- The pattern is: height 33 = 32 + 1, height 65 = 64 + 1, etc.
