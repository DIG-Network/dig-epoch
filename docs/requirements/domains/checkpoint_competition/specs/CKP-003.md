# CKP-003: submit_checkpoint with Score

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)

## Summary

Defines the `submit_checkpoint` method that accepts checkpoint submissions during the `Collecting` phase. Each submission's score is computed as `stake_percentage * block_count`. If a submission's score exceeds the current leader, it becomes the new winner and the competition transitions to `WinnerSelected`.

## Specification

```rust
impl CheckpointCompetition {
    pub fn submit_checkpoint(&mut self, submission: CheckpointSubmission) -> Result<()> {
        // 1. Verify status == Collecting (or WinnerSelected for higher-score challenge)
        // 2. Verify submission.epoch == self.epoch
        // 3. Compute score = stake_percentage * block_count
        // 4. If score > current winner score, update current_winner
        // 5. Reject with ScoreNotHigher if not beating current leader
        Ok(())
    }
}
```

- MUST verify `status` is `Collecting` or `WinnerSelected` (accepting challenges to current leader).
- MUST verify that `submission.epoch` matches `self.epoch`. Returns `EpochMismatch` otherwise.
- MUST compute `score = stake_percentage * block_count` for the submission.
- If `score > current_winner_score` (or no current winner exists), MUST update `current_winner` to the new submission index and transition status to `WinnerSelected { winner_hash, winner_score }`.
- If `score <= current_winner_score`, MUST reject with `ScoreNotHigher { current, submitted }`.

## Acceptance Criteria

- [ ] First valid submission sets current_winner and transitions to WinnerSelected.
- [ ] Higher-scoring submission replaces current_winner and updates WinnerSelected data.
- [ ] Score is computed as `stake_percentage * block_count`.
- [ ] Returns `ScoreNotHigher` when submission score does not exceed current leader.
- [ ] Returns `EpochMismatch` when submission epoch does not match competition epoch.
- [ ] Rejects submission when status is `Pending`.
- [ ] Rejects submission when status is `Finalized`.
- [ ] Rejects submission when status is `Failed`.
- [ ] Submission is appended to `submissions` vector regardless of score outcome.

## Implementation Notes

- The score formula `stake_percentage * block_count` incentivizes validators with both high stake and high block production.
- `stake_percentage` is typically expressed as an integer (e.g., 0-10000 for basis points or 0-100 for percentage).
- Submissions are always recorded in the `submissions` vector for auditability, even if rejected by score.
- The `WinnerSelected` status carries the winner's hash and score for quick access without indexing.
