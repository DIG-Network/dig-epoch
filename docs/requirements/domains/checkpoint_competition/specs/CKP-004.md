## Summary

Defines the `finalize_competition` method that transitions the competition from `WinnerSelected` to `Finalized`, anchoring the winning checkpoint to an L1 block height. Also defines `get_competition` for reading the current competition state.

## Specification

### finalize_competition

```rust
impl CheckpointCompetition {
    pub fn finalize_competition(&mut self, l1_height: u32) -> Result<Bytes32> {
        // 1. Verify status == WinnerSelected
        // 2. Extract winner_hash from WinnerSelected
        // 3. Transition to Finalized { winner_hash, l1_height }
        // 4. Set checkpoint on current EpochInfo
        // 5. Return winner_hash
        Ok(winner_hash)
    }
}
```

- MUST verify that `status` is `WinnerSelected`. If not, MUST return an error.
- MUST extract `winner_hash` from the `WinnerSelected` status.
- MUST transition `status` to `Finalized { winner_hash, l1_height }`.
- MUST set the checkpoint on the current `EpochInfo` using the winner's data.
- MUST return the `winner_hash` on success.

- MUST return the current competition state including status, submissions, and winner.

## Acceptance Criteria

- [ ] Transitions from `WinnerSelected` to `Finalized` with correct `winner_hash` and `l1_height`.
- [ ] Returns the `winner_hash` on success.
- [ ] Sets checkpoint on `EpochInfo` with the winner's data.
- [ ] Returns error when status is `Pending`.
- [ ] Returns error when status is `Collecting`.
- [ ] Returns error when status is already `Finalized`.
- [ ] Returns error when status is `Failed`.
- [ ] `get_competition()` returns current competition state.
- [ ] `l1_height` is preserved in the `Finalized` status.

## Implementation Notes

- The `l1_height` anchors the checkpoint to a specific L1 block, enabling cross-chain verification.
- After finalization, no further submissions or state changes are allowed.
- The `EpochInfo` update links the competition result to the epoch's metadata.
- `get_competition` is a simple accessor, useful for querying state from external components.
