# CKP-001: CheckpointCompetition and CompetitionStatus

## Summary

Defines the `CheckpointCompetition` struct that manages checkpoint submissions for a given epoch and the `CompetitionStatus` enum that tracks the competition state machine. The competition collects submissions with scores and determines a winner.

## Specification

### CheckpointCompetition

`CheckpointCompetition` MUST contain the following fields:

| Field            | Type                        | Description                                  |
|------------------|-----------------------------|----------------------------------------------|
| `epoch`          | `u64`                       | The epoch this competition belongs to        |
| `submissions`    | `Vec<CheckpointSubmission>` | All checkpoint submissions received          |
| `status`         | `CompetitionStatus`         | Current state of the competition             |
| `current_winner` | `Option<usize>`             | Index into submissions of the current leader |

### CompetitionStatus

```rust
pub enum CompetitionStatus {
    Pending,
    Collecting,
    WinnerSelected {
        winner_hash: Bytes32,
        winner_score: u64,
    },
    Finalized {
        winner_hash: Bytes32,
        l1_height: u32,
    },
    Failed,
}
```

- `Pending` - Competition created but not yet accepting submissions.
- `Collecting` - Actively accepting checkpoint submissions.
- `WinnerSelected` - A winning submission has been identified by score.
- `Finalized` - Winner confirmed and anchored to an L1 height.
- `Failed` - Competition ended due to timeout or error.

## Acceptance Criteria

- [ ] `CheckpointCompetition` struct contains all four required fields with correct types.
- [ ] `CompetitionStatus` defines all five variants with correct associated data.
- [ ] `WinnerSelected` carries `winner_hash: Bytes32` and `winner_score: u64`.
- [ ] `Finalized` carries `winner_hash: Bytes32` and `l1_height: u32`.
- [ ] `current_winner` is `Option<usize>` indexing into `submissions`.

## Implementation Notes

- `current_winner` uses an index into the `submissions` vector rather than cloning the submission, keeping the struct efficient.
- `CompetitionStatus` variants with data use named fields for clarity.
- The `Bytes32` type represents a 32-byte hash (checkpoint hash).
