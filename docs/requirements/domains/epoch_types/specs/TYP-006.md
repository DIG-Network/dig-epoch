## Summary

EpochBlockLink records the parent-to-child hash relationship between consecutive blocks within an epoch. It is used for block continuity validation in L1 finalization payloads to prove that an epoch's blocks form a valid chain.

## Specification

EpochBlockLink MUST define the following structure:

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct EpochBlockLink {
    pub parent_hash: Bytes32,
    pub block_hash: Bytes32,
}
```

- `parent_hash` is the hash of the parent block
- `block_hash` is the hash of the current (child) block
- Together they prove that `block_hash` was produced as a successor to `parent_hash`

## Acceptance Criteria

- [ ] EpochBlockLink contains parent_hash (Bytes32) and block_hash (Bytes32)
- [ ] EpochBlockLink derives Debug, Clone, Serialize, Deserialize
- [ ] Both fields are publicly accessible
- [ ] parent_hash and block_hash use chia-protocol::Bytes32
- [ ] Serialization round-trip preserves both fields

## Implementation Notes

- EpochBlockLink is one of the six serializable types in the crate (see SPEC Section 11.1)
- The link represents a single edge in the epoch's block chain graph
- A complete epoch of 32 blocks would have 31 EpochBlockLink entries (each block except the first has a parent within the epoch)
- The first block in an epoch links back to the previous epoch's checkpoint block
- Used in L1 finalization payloads alongside the epoch's Merkle block root
