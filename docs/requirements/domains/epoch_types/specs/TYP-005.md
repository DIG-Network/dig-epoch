## Summary

EpochEvent is an enum of events emitted by the EpochManager for downstream notification. Events cover the full epoch lifecycle: start, phase changes, finalization, and failure. They are used for telemetry, logging, and driver coordination.

## Specification

EpochEvent MUST define the following variants:

```rust
#[derive(Debug, Clone)]
pub enum EpochEvent {
    EpochStarted {
        epoch: u64,
        l1_height: u32,
    },
    PhaseChanged {
        epoch: u64,
        from: EpochPhase,
        to: EpochPhase,
        l1_height: u32,
    },
    EpochFinalized {
        epoch: u64,
        checkpoint: Checkpoint,
    },
    EpochFailed {
        epoch: u64,
    },
}
```

- `EpochStarted` is emitted when a new epoch begins, carrying the epoch number and the L1 height at which it started
- `PhaseChanged` is emitted on each phase transition, carrying the epoch, the source and target phases, and the L1 height
- `EpochFinalized` is emitted when epoch finalization completes successfully, carrying the epoch and the winning checkpoint
- `EpochFailed` is emitted when epoch finalization fails, carrying only the epoch number

## Acceptance Criteria

- [ ] EpochEvent defines exactly four variants: EpochStarted, PhaseChanged, EpochFinalized, EpochFailed
- [ ] EpochEvent derives Debug and Clone
- [ ] EpochStarted carries epoch (u64) and l1_height (u32)
- [ ] PhaseChanged carries epoch (u64), from (EpochPhase), to (EpochPhase), l1_height (u32)
- [ ] EpochFinalized carries epoch (u64) and checkpoint (Checkpoint)
- [ ] EpochFailed carries epoch (u64)
- [ ] All variants are constructable and support pattern matching

## Implementation Notes

- EpochEvent does not derive Serialize/Deserialize because it contains Checkpoint which may have its own serialization strategy
- Events are emitted but not persisted -- they are consumed by telemetry and driver components
- PhaseChanged reuses the EpochPhase type for its from/to fields
- Checkpoint in EpochFinalized is the full dig-block::Checkpoint, not just the hash
- EpochFailed is intentionally minimal (just epoch number) -- the failure reason is communicated through error types
