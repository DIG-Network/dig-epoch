# TYP-001: EpochPhase and PhaseTransition

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Sections 3.2, 3.3](../../../../resources/SPEC.md)

## Summary

EpochPhase is a four-variant enum representing the lifecycle phase of an epoch, driven by L1 block height progress. PhaseTransition records a phase change event for telemetry and downstream notification. Together they form the foundation of the epoch phase state machine.

## Specification

EpochPhase MUST define four variants representing the epoch lifecycle phases:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum EpochPhase {
    /// Block production (0-50% of L1 window).
    /// Validators propose and attest L2 blocks.
    BlockProduction,

    /// Checkpoint submission (50-75% of L1 window).
    /// Validators submit competing checkpoint summaries.
    Checkpoint,

    /// Finalization (75-100% of L1 window).
    /// Winning checkpoint is selected, rewards are computed.
    Finalization,

    /// Epoch is complete (>= 100% of L1 window).
    /// No further operations; epoch is ready to advance.
    Complete,
}
```

PhaseTransition MUST record the details of a phase change:

```rust
#[derive(Debug, Clone)]
pub struct PhaseTransition {
    pub epoch: u64,
    pub from: EpochPhase,
    pub to: EpochPhase,
    pub l1_height: u32,
}
```

**EpochPhase methods:**

| Method | Signature | Description |
|--------|-----------|-------------|
| `index()` | `(&self) -> usize` | BlockProduction=0, Checkpoint=1, Finalization=2, Complete=3 |
| `next()` | `(&self) -> Option<EpochPhase>` | BlockProduction->Some(Checkpoint)->Some(Finalization)->Some(Complete)->None |
| `previous()` | `(&self) -> Option<EpochPhase>` | Complete->Some(Finalization)->Some(Checkpoint)->Some(BlockProduction)->None |
| `name()` | `(&self) -> &'static str` | "BlockProduction", "Checkpoint", "Finalization", "Complete" |
| `allows_block_production()` | `(&self) -> bool` | true only for BlockProduction |
| `allows_checkpoint_submission()` | `(&self) -> bool` | true only for Checkpoint |
| `allows_finalization()` | `(&self) -> bool` | true only for Finalization |

**Phase permissions table:**

| Phase | allows_block_production | allows_checkpoint_submission | allows_finalization |
|-------|------------------------|-----------------------------|--------------------|
| BlockProduction | true | false | false |
| Checkpoint | false | true | false |
| Finalization | false | false | true |
| Complete | false | false | false |

## Acceptance Criteria

- [ ] EpochPhase defines exactly four variants: BlockProduction, Checkpoint, Finalization, Complete
- [ ] EpochPhase derives Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize
- [ ] EpochPhase variants can be compared for equality via PartialEq/Eq
- [ ] EpochPhase variants can be used as HashMap keys via Hash
- [ ] EpochPhase variants can be serialized/deserialized via serde
- [ ] index() returns 0 for BlockProduction, 1 for Checkpoint, 2 for Finalization, 3 for Complete
- [ ] next() returns the correct successor or None for Complete
- [ ] previous() returns the correct predecessor or None for BlockProduction
- [ ] name() returns "BlockProduction", "Checkpoint", "Finalization", "Complete" respectively
- [ ] allows_block_production() returns true only for BlockProduction
- [ ] allows_checkpoint_submission() returns true only for Checkpoint
- [ ] allows_finalization() returns true only for Finalization
- [ ] Complete phase returns false for all three allows_* methods
- [ ] PhaseTransition contains epoch (u64), from (EpochPhase), to (EpochPhase), l1_height (u32)
- [ ] PhaseTransition derives Debug and Clone
- [ ] PhaseTransition fields are publicly accessible

## Implementation Notes

- EpochPhase is the most widely used type in the crate -- it is referenced by EpochInfo, PhaseTransition, EpochEvent, EpochError, and the phase state machine
- Copy derive allows EpochPhase to be passed by value without cloning, which is appropriate for a small enum
- Hash derive enables use as a key in HashMaps and HashSets for phase-based indexing
- The phase ordering (BlockProduction=0, Checkpoint=1, Finalization=2, Complete=3) is used by the phase state machine (see phase_machine domain) for monotonicity checks
- PhaseTransition is returned by EpochManager::update_phase() when a phase change occurs
