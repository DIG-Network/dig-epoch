# STR-005: Test Infrastructure

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)

> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)

## Summary

The crate must provide reusable test helper utilities that simplify writing tests across all domains. These helpers create deterministic test fixtures for the EpochManager, simulate phase progression, generate mock checkpoint submissions, and build multi-block epoch chains. Without these helpers, each test module would duplicate boilerplate setup code.

## Specification

The crate MUST provide the following test helper functions:

**Helper 1: Create test EpochManager**

```rust
/// Creates an EpochManager with deterministic test parameters.
/// - network_id: fixed 32-byte value (e.g., all 0x01)
/// - genesis_l1_height: 100 (allows room for pre-genesis L1 blocks)
/// - initial_state_root: fixed 32-byte value (e.g., all 0xAA)
pub fn test_epoch_manager() -> EpochManager
```

**Helper 2: Advance through phases**

```rust
/// Advances the EpochManager through all four phases by simulating
/// L1 height progression. Returns the final phase (Complete) and
/// the sequence of PhaseTransitions observed.
///
/// Starting from the current epoch's start_l1_height, calls
/// update_phase() at heights that trigger each phase boundary:
/// - BlockProduction -> Checkpoint (50% of window)
/// - Checkpoint -> Finalization (75% of window)
/// - Finalization -> Complete (100% of window)
pub fn advance_through_phases(
    manager: &EpochManager,
) -> Vec<PhaseTransition>
```

**Helper 3: Create mock checkpoint submission**

```rust
/// Creates a mock CheckpointSubmission with configurable scoring
/// parameters. The submission has valid structure but uses synthetic
/// keys and signatures (not cryptographically valid).
///
/// Score = stake_percentage * block_count (per competition rules).
pub fn mock_checkpoint_submission(
    epoch: u64,
    stake_percentage: u64,
    block_count: u32,
) -> CheckpointSubmission
```

**Helper 4: Build N-block epoch chain**

```rust
/// Records N blocks into the current epoch by calling record_block()
/// N times with the specified fee and transaction count per block.
///
/// Returns the total fees and total transactions accumulated.
pub fn build_n_block_epoch(
    manager: &EpochManager,
    n: u32,
    fee_per_block: u64,
    tx_per_block: u64,
) -> (u64, u64)
```

## Acceptance Criteria

- `test_epoch_manager()` returns a valid EpochManager at epoch 0 with `BlockProduction` phase
- `advance_through_phases()` transitions through all four phases and returns the correct number of PhaseTransition records (3 transitions)
- `mock_checkpoint_submission()` returns a CheckpointSubmission with the specified epoch and scoring parameters
- `build_n_block_epoch()` records exactly N blocks and returns correct accumulated totals
- All helpers produce deterministic, repeatable results
- Helpers are available in test builds but not in production builds

## Implementation Notes

- Helpers SHOULD be in a `test_helpers` module gated with `#[cfg(test)]` in the library, or in a shared test utilities file under `tests/`
- The mock checkpoint submission helper needs to construct synthetic `Checkpoint`, `Signature`, and `PublicKey` values; these do not need to be cryptographically valid for unit tests
- `advance_through_phases()` should compute the L1 heights from the epoch's start and end heights using the phase boundary percentages
- `build_n_block_epoch()` should verify that N does not exceed `BLOCKS_PER_EPOCH` (32) and return an error or panic if it does

## Verification

### Test Plan

| Test | Type | Description | Expected Result |
|------|------|-------------|-----------------|
| test_helper_epoch_manager | Unit | Call `test_epoch_manager()`, verify epoch 0 and BlockProduction phase | Valid EpochManager returned |
| test_helper_advance_phases | Unit | Create test manager, call `advance_through_phases()` | Returns 3 PhaseTransitions in order: BP->CK, CK->FN, FN->CO |
| test_helper_mock_submission | Unit | Call `mock_checkpoint_submission(1, 75, 32)` | Returns CheckpointSubmission for epoch 1 |
| test_helper_build_epoch | Unit | Create test manager, call `build_n_block_epoch(manager, 32, 1000, 5)` | Returns (32000, 160); manager shows 32 blocks produced |
| test_helper_deterministic | Unit | Call each helper twice, compare results | Results are identical across calls |
| test_helper_build_epoch_overflow | Unit | Call `build_n_block_epoch(manager, 33, ...)` with N > BLOCKS_PER_EPOCH | Panics or returns error |
