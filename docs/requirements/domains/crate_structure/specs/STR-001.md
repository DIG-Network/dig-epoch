# STR-001: Cargo.toml Dependencies

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)

## Summary

The dig-epoch crate's Cargo.toml must declare all required dependencies with specific version constraints. Each dependency serves a distinct, non-overlapping purpose: DIG ecosystem crates for block and network types, Chia ecosystem crates for cryptographic primitives and Merkle tree operations, and utility crates for serialization, error handling, and concurrency.

## Specification

Cargo.toml MUST include the following `[dependencies]` entries:

**DIG ecosystem:**
```toml
dig-block = "0.1"        # Checkpoint, CheckpointSubmission, SignerBitmap, L2BlockHeader
dig-constants = "0.10"   # NetworkConstants, network ID, genesis challenge
```

`dig-constants` is pinned to `0.10` — the latest published line. From `0.10.0`
onward that crate depends on the chia **0.36** cohort (`chia-protocol ^0.36.1`,
`chia-consensus ^0.36.1`), whereas dig-epoch and `dig-block` depend on the chia
**0.26/0.30** cohort. Cargo therefore links two incompatible copies of
`chia-protocol` and `chia-consensus`.

This is sound only because dig-epoch links `dig-constants` without calling it:
no `dig_constants` value ever crosses into dig-epoch's own types. A chia type
obtained from `dig-constants` is a *different* type from dig-epoch's
`chia_protocol::Bytes32` and will not type-check. `NetworkConstants` and the
genesis challenge MUST NOT be consumed from `dig-constants` until `dig-block`
and dig-epoch have both moved to the chia 0.36 cohort.

**Chia ecosystem:**
```toml
chia-protocol = "0.26"   # Bytes32 - universal 32-byte hash type
chia-bls = "0.26"        # Signature, PublicKey, aggregate(), aggregate_verify()
chia-consensus = "0.26"  # compute_merkle_set_root(), validate_merkle_proof()
chia-sdk-types = "0.30"  # MerkleTree, MerkleProof, MAINNET_CONSTANTS
chia-sdk-signer = "0.30" # AggSigConstants - domain separation for signing digest
chia-sha2 = "0.26"       # Sha256 - SHA-256 hasher for checkpoint data, digests
clvm-utils = "0.26"      # tree_hash(), TreeHash - CLVM tree hashing semantics
```

**Utility crates:**
```toml
bincode = "*"            # Compact binary serialization for epoch types
serde = { version = "*", features = ["derive"] }  # Serialize/Deserialize derives
thiserror = "*"          # Error type derivation
parking_lot = "*"        # RwLock for EpochManager interior mutability
```

## Acceptance Criteria

- Cargo.toml contains all 13 listed dependencies
- `dig-block` pinned to 0.1; `dig-constants` pinned to 0.10
- Chia crates pinned to specified versions (0.26 or 0.30)
- serde includes the `derive` feature
- `cargo check` completes successfully with all dependencies resolved
- No dependency is duplicated or unnecessary

## Implementation Notes

- Version constraints follow the Chia Rust ecosystem versioning scheme where `chia-sdk-types` and `chia-sdk-signer` are at 0.30 while lower-level crates (`chia-protocol`, `chia-bls`, `chia-sha2`, `chia-consensus`, `clvm-utils`) are at 0.26
- `parking_lot` is preferred over `std::sync::RwLock` for performance and lack of poisoning
- `bincode` version is not pinned; the latest compatible version should be used
- `thiserror` version is not pinned; the latest compatible version should be used
