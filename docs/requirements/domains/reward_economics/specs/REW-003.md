## Summary

Defines the fee distribution functions that split transaction fees between the block proposer and a burn mechanism. The split is 50/50: the proposer receives half of all fees and the remainder is burned.

## Specification

### proposer_fee_share

```rust
pub fn proposer_fee_share(total_fees: u64) -> u64 {
    total_fees * FEE_PROPOSER_SHARE_PCT / 100
}
```

### burned_fee_remainder

```rust
pub fn burned_fee_remainder(total_fees: u64) -> u64 {
    total_fees - proposer_fee_share(total_fees)
}
```

### Constants

| Constant                | Value | Description                         |
|-------------------------|-------|-------------------------------------|
| `FEE_PROPOSER_SHARE_PCT`| 50    | Percentage of fees going to proposer |

- `proposer_fee_share` computes the proposer's portion as `total_fees * 50 / 100`.
- `burned_fee_remainder` computes the burned portion as the difference between total fees and the proposer's share.
- The burned remainder accounts for any integer rounding (the burn side absorbs the rounding remainder).

## Acceptance Criteria

- [ ] `proposer_fee_share(total_fees)` returns `total_fees * FEE_PROPOSER_SHARE_PCT / 100`.
- [ ] `burned_fee_remainder(total_fees)` returns `total_fees - proposer_fee_share(total_fees)`.
- [ ] `proposer_fee_share + burned_fee_remainder == total_fees` for all inputs.
- [ ] Returns 0 for both functions when `total_fees` is 0.
- [ ] Handles odd fee values correctly (rounding goes to burn side).
- [ ] `FEE_PROPOSER_SHARE_PCT` equals 50.

## Implementation Notes

- Integer division means odd fee values have a 1-mojo rounding difference; by convention the burn side absorbs this.
- The 50/50 split balances proposer incentives with deflationary pressure from burning.
- Both functions are pure and deterministic.
