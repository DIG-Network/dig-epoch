# REW-004: Epoch Reward Distribution (5-Role Split)

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 8.4](../../../../resources/SPEC.md)

## Summary

Defines the `compute_reward_distribution` function that splits the total epoch reward across five roles and combines it with the fee distribution. The 5-role split incentivizes all participants in the epoch lifecycle: proposers, attesters, EF spawners, score submitters, and finalizers.

## Specification

```rust
pub fn compute_reward_distribution(
    epoch: u64,
    total_reward: u64,
    total_fees: u64,
) -> RewardDistribution {
    RewardDistribution {
        epoch,
        proposer_reward: total_reward * 10 / 100,
        attester_reward: total_reward * 80 / 100,
        ef_spawner_reward: total_reward * 3 / 100,
        score_submitter_reward: total_reward * 4 / 100,
        finalizer_reward: total_reward * 3 / 100,
        proposer_fee_share: proposer_fee_share(total_fees),
        burned_fees: burned_fee_remainder(total_fees),
    }
}
```

### Reward Split

| Role             | Percentage | Description                                |
|------------------|------------|--------------------------------------------|
| Proposer         | 10%        | Block proposer reward share                |
| Attester         | 80%        | Attestation validator reward share         |
| EF Spawner       | 3%         | Epoch-first spawner reward share           |
| Score Submitter  | 4%         | Checkpoint score submission reward share   |
| Finalizer        | 3%         | Competition finalizer reward share         |

- The five role percentages MUST sum to 100%.
- `RewardDistribution` MUST also contain the fee split: `proposer_fee_share` and `burned_fees`.
- Fee fields are computed via `proposer_fee_share()` and `burned_fee_remainder()` (see REW-003).

## Acceptance Criteria

- [ ] `proposer_reward` equals `total_reward * 10 / 100`.
- [ ] `attester_reward` equals `total_reward * 80 / 100`.
- [ ] `ef_spawner_reward` equals `total_reward * 3 / 100`.
- [ ] `score_submitter_reward` equals `total_reward * 4 / 100`.
- [ ] `finalizer_reward` equals `total_reward * 3 / 100`.
- [ ] All five reward shares sum to `total_reward` (accounting for integer rounding).
- [ ] `RewardDistribution` contains `proposer_fee_share` and `burned_fees`.
- [ ] Fee fields are computed correctly from `total_fees`.
- [ ] `epoch` field matches the input epoch.

## Implementation Notes

- Integer division may cause rounding dust; the largest share (attester at 80%) naturally absorbs this since `10 + 80 + 3 + 4 + 3 = 100` exactly, but individual integer divisions may not sum precisely. Implementations should ensure the sum of all shares equals `total_reward` by adjusting the largest share.
- The proposer receives both a reward share (10% of block rewards) and a fee share (50% of transaction fees), making proposer economics the sum of `proposer_reward + proposer_fee_share`.
- The 80% attester share reflects that attestation is the primary security function of the network.
