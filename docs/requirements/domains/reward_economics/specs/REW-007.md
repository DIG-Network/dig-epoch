## Summary

RewardDistribution is the per-epoch reward allocation across the five reward roles plus fee distribution. It is produced by `compute_reward_distribution()` and stored by `EpochManager::store_rewards()`.

## Specification

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RewardDistribution {
    pub epoch: u64,
    pub total_reward: u64,            // Base epoch reward (from halving schedule)
    pub proposer_reward: u64,         // 10% of total_reward
    pub attester_reward: u64,         // 80% of total_reward
    pub ef_spawner_reward: u64,       // 3% of total_reward
    pub score_submitter_reward: u64,  // 4% of total_reward
    pub finalizer_reward: u64,        // 3% of total_reward
    pub total_fees: u64,              // Fees collected in this epoch
    pub proposer_fee_share: u64,      // 50% of total_fees
    pub burned_fees: u64,             // 50% of total_fees
}
```

Key rules:
- All 10 fields MUST be present and publicly accessible
- The five reward share fields MUST sum to total_reward (with possible integer rounding)
- proposer_fee_share + burned_fees MUST equal total_fees
- This struct is produced by compute_reward_distribution() (REW-004)

## Acceptance Criteria

- [ ] RewardDistribution contains exactly 10 fields with correct names and types
- [ ] RewardDistribution derives Debug, Clone, Serialize, Deserialize
- [ ] All fields are publicly accessible
- [ ] proposer_reward = total_reward * 10 / 100
- [ ] attester_reward = total_reward * 80 / 100
- [ ] ef_spawner_reward = total_reward * 3 / 100
- [ ] score_submitter_reward = total_reward * 4 / 100
- [ ] finalizer_reward = total_reward * 3 / 100
- [ ] proposer_fee_share = total_fees * 50 / 100
- [ ] burned_fees = total_fees - proposer_fee_share
- [ ] Bincode round-trip serialization preserves all fields

## Implementation Notes

- RewardDistribution is stored per-epoch in the EpochManager's rewards map
- Retrieved via EpochManager::get_rewards(epoch)
- The reward shares use integer division, so rounding may cause the sum to be slightly less than total_reward
- All values are in mojos (u64)
