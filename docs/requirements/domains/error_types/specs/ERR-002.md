# ERR-002: CheckpointCompetitionError Enum

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 10.2](../../../../resources/SPEC.md)

## Summary

CheckpointCompetitionError covers all failure modes within the checkpoint competition lifecycle. It is a separate error type from EpochError because competition errors represent a distinct error domain (multi-submission score-based competition) with different semantics from epoch lifecycle errors.

## Specification

```rust
#[derive(Debug, Clone, thiserror::Error)]
pub enum CheckpointCompetitionError {
    #[error("Invalid checkpoint data: {0}")]
    InvalidData(String),

    #[error("Checkpoint competition not found for epoch {0}")]
    NotFound(u64),

    #[error("Score not higher: current {current}, submitted {submitted}")]
    ScoreNotHigher { current: u64, submitted: u64 },

    #[error("Epoch mismatch: expected {expected}, got {got}")]
    EpochMismatch { expected: u64, got: u64 },

    #[error("Competition already finalized")]
    AlreadyFinalized,

    #[error("Competition not started")]
    NotStarted,
}
```

## Acceptance Criteria

- [ ] CheckpointCompetitionError defines exactly 6 variants: InvalidData, NotFound, ScoreNotHigher, EpochMismatch, AlreadyFinalized, NotStarted
- [ ] CheckpointCompetitionError derives Debug and Clone
- [ ] CheckpointCompetitionError implements std::error::Error via thiserror
- [ ] InvalidData(String) carries a descriptive validation message
- [ ] NotFound(u64) carries the epoch number
- [ ] ScoreNotHigher carries current and submitted u64 fields
- [ ] EpochMismatch carries expected and got u64 fields
- [ ] AlreadyFinalized is a unit variant
- [ ] NotStarted is a unit variant
- [ ] Display output for each variant matches the specified error messages

## Implementation Notes

- CheckpointCompetitionError is separate from EpochError (SPEC Design Decision #12) to allow callers to pattern-match on the error domain
- This error type is converted to EpochError::Competition via the From impl (ERR-003)
- InvalidData uses String for flexible validation error messages
- ScoreNotHigher carries both scores for diagnostic comparison
- AlreadyFinalized and NotStarted are unit variants because no additional context is needed
- NotFound is used when querying for a competition for an epoch that has no competition entry
