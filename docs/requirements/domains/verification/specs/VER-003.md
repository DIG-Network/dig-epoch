# VER-003: Epoch Withdrawals Root

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 7.3](../../../../resources/SPEC.md)

## Summary

compute_epoch_withdrawals_root computes an order-independent Merkle set root over all withdrawal hashes in an epoch. This root commits to the set of withdrawals processed during the epoch and is included in the epoch checkpoint. The order-independence ensures that any permutation of the same withdrawal set produces the same root.

## Specification

compute_epoch_withdrawals_root MUST be implemented as follows:

```rust
pub fn compute_epoch_withdrawals_root(withdrawal_hashes: &[Bytes32]) -> Bytes32 {
    if withdrawal_hashes.is_empty() {
        return EMPTY_ROOT;
    }

    compute_merkle_set_root(withdrawal_hashes)
}
```

Key rules:
- MUST use chia-consensus::compute_merkle_set_root() for Merkle set root computation
- MUST return EMPTY_ROOT when withdrawal_hashes is an empty slice
- The result MUST be order-independent: the same set of withdrawal hashes in any order MUST produce the same root
- Uses tagged hashing consistent with dig-block: leaf = SHA-256(0x01 || data), node = SHA-256(0x02 || left || right)

## Acceptance Criteria

- [ ] Returns EMPTY_ROOT for an empty slice
- [ ] Computes root using chia-consensus::compute_merkle_set_root()
- [ ] Single withdrawal hash produces correct Merkle set root
- [ ] Multiple withdrawal hashes produce correct Merkle set root
- [ ] Order-independent: same hashes in different order produce identical root
- [ ] Tagged hashing is used (0x01 leaf prefix, 0x02 node prefix)
- [ ] Deterministic: same inputs always produce same output

## Implementation Notes

- EMPTY_ROOT is the SHA-256 of the empty string
- compute_merkle_set_root is from chia-consensus and implements the same Merkle set algorithm used in Chia's block validation
- The order-independence property distinguishes this from VER-001 (which is order-dependent)
- This matches the approach used in dig-block for additions_root (HSH-004) and removals_root (HSH-005)
- The resulting root is stored in the Checkpoint struct as withdrawals_root
