# VER-005: Aggregate Signature Construction

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 7.6](../../../../resources/SPEC.md)

## Summary

stored_checkpoint_from_epoch_sign_material_with_aggregate_v1 takes sign material, individual validator signatures, public keys, a signer bitmap, and a submitter index, and produces a CheckpointSubmission with an aggregated BLS signature. This is the final step before a checkpoint can be submitted to L1 for anchoring.

## Specification

```rust
/// Constructs an aggregate checkpoint submission from per-validator signatures.
///
/// Uses chia-bls::aggregate() to combine individual BLS signatures into a
/// single aggregate signature, and chia-bls::aggregate_verify() to validate
/// the result against the signing digest and validator public keys.
pub fn stored_checkpoint_from_epoch_sign_material_with_aggregate_v1(
    material: &EpochCheckpointSignMaterial,
    validator_set: &[(u32, PublicKey)],   // (index, pubkey) pairs
    per_validator: &[(u32, PublicKey, Signature)],  // (index, pubkey, sig) per signer
    submitter: u32,
) -> Result<CheckpointSubmission, EpochError>
```

Key rules:
- MUST aggregate all provided per-validator signatures via chia-bls::aggregate()
- MUST aggregate the corresponding public keys into a single aggregate public key
- MUST construct a CheckpointSubmission with the score from the sign material
- `validator_set` provides the full set of (index, pubkey) pairs for the active validator set
- `per_validator` provides (index, pubkey, signature) tuples for each signing validator
- The signer bitmap MUST be computed from `validator_set` and `per_validator` to reflect which validators contributed signatures
- submission_height and submission_coin MUST be None (not yet submitted to L1)
- MUST return an error if signature aggregation fails (e.g., empty per_validator)

## Acceptance Criteria

- [ ] Aggregates per-validator signatures via chia-bls::aggregate()
- [ ] Aggregates public keys into a single aggregate public key
- [ ] Constructs CheckpointSubmission with correct checkpoint data
- [ ] Score in CheckpointSubmission matches material.score
- [ ] submitter field is stored correctly
- [ ] submission_height is None
- [ ] submission_coin is None
- [ ] Signer bitmap is computed from validator_set and per_validator
- [ ] Returns error on empty per_validator
- [ ] Aggregate signature is valid under aggregate public key for signing_digest
- [ ] Function signature matches: `(material, validator_set: &[(u32, PublicKey)], per_validator: &[(u32, PublicKey, Signature)], submitter: u32) -> Result<CheckpointSubmission, EpochError>`

## Implementation Notes

- chia-bls::aggregate() implements BLS signature aggregation per the BLS12-381 curve
- Aggregate public key is computed by summing individual public keys on the curve
- The resulting CheckpointSubmission is ready for L1 submission once submission_height and submission_coin are recorded
- The signer bitmap is derived from comparing `validator_set` against `per_validator` to determine which validators signed
- `validator_set` provides the complete active validator set; `per_validator` provides only those who signed
- This function is the bridge between the signing phase (VER-004) and the submission phase
