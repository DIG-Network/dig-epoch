# VER-001: Epoch Block Root

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 7.1](../../../../resources/SPEC.md)

## Summary

compute_epoch_block_root computes the canonical Merkle root over all block hashes in an epoch. This root commits to the ordered set of blocks produced during the epoch and is included in the epoch checkpoint for L1 anchoring.

## Specification

compute_epoch_block_root MUST be implemented as follows:

```rust
pub fn compute_epoch_block_root(block_hashes: &[Bytes32]) -> Bytes32 {
    if block_hashes.is_empty() {
        return EMPTY_ROOT;
    }

    MerkleTree::new(block_hashes).root()
}
```

Key rules:
- MUST use chia-sdk-types::MerkleTree for Merkle tree construction
- Block hashes MUST be in epoch order (the order blocks were produced within the epoch)
- MUST return EMPTY_ROOT when block_hashes is an empty slice
- Given the same ordered set of block hashes, MUST always produce the same Bytes32 (deterministic)
- Changing the order of block hashes MUST produce a different root

## Acceptance Criteria

- [ ] Returns EMPTY_ROOT for an empty slice
- [ ] Computes Merkle root using chia-sdk-types::MerkleTree
- [ ] Block hashes are consumed in epoch order
- [ ] Single block hash produces MerkleTree root over one leaf
- [ ] Multiple block hashes produce correct Merkle root
- [ ] Deterministic: same inputs always produce same output
- [ ] Order-sensitive: different orderings produce different roots

## Implementation Notes

- EMPTY_ROOT is the SHA-256 of the empty string, consistent with dig-block conventions
- chia-sdk-types::MerkleTree uses tagged hashing internally (see dig-block HSH-007)
- The resulting root is stored in the Checkpoint struct as block_root
- This function is called during checkpoint construction (VER-004)
