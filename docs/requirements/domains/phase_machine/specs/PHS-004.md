## Summary

Defines the phase-gating invariant: certain epoch operations are only valid during specific phases. When called in the wrong phase, these operations MUST reject with `EpochError::PhaseMismatch { expected, got }` to enforce lifecycle correctness.

## Specification

### Phase-Gated Operations

| Operation              | Required Phase     | Error on Mismatch                                      |
|------------------------|--------------------|--------------------------------------------------------|
| `record_block`         | `BlockProduction`  | `EpochError::PhaseMismatch { expected: BlockProduction, got: <current> }` |
| `submit_checkpoint`    | `Checkpoint`       | `EpochError::PhaseMismatch { expected: Checkpoint, got: <current> }`      |
| `finalize_competition` | `Finalization`     | `EpochError::PhaseMismatch { expected: Finalization, got: <current> }`    |

### Error Type

```rust
pub enum EpochError {
    PhaseMismatch {
        expected: EpochPhase,
        got: EpochPhase,
    },
    // ... other variants
}
```

The `PhaseMismatch` variant MUST include both the `expected` phase and the `got` (actual) phase so callers can produce informative error messages.

### Enforcement Pattern

Each phase-gated operation MUST check the current phase before performing its work:

```rust
fn record_block(&self, fees: u64, tx_count: u64) -> Result<()> {
    let inner = self.inner.read();
    if inner.current_epoch.phase != EpochPhase::BlockProduction {
        return Err(EpochError::PhaseMismatch {
            expected: EpochPhase::BlockProduction,
            got: inner.current_epoch.phase,
        });
    }
    // ... proceed with operation
}
```

## Acceptance Criteria

- [ ] `record_block` rejects with `PhaseMismatch` when phase is not `BlockProduction`.
- [ ] `submit_checkpoint` rejects with `PhaseMismatch` when phase is not `Checkpoint`.
- [ ] `finalize_competition` rejects with `PhaseMismatch` when phase is not `Finalization`.
- [ ] `PhaseMismatch` error contains the correct `expected` phase.
- [ ] `PhaseMismatch` error contains the correct `got` phase.
- [ ] Operations succeed when called in their required phase (no false rejections).

## Implementation Notes

- Phase checks MUST be performed before any state mutation to ensure atomicity.
- The check pattern is consistent across all gated operations: read the current phase, compare to the required phase, return error if mismatched.
- This enforcement ensures the epoch lifecycle is valid by construction.
