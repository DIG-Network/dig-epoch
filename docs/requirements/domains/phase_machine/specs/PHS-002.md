## Summary

Defines the phase tracking methods on `EpochManager` that allow querying the current phase and updating it based on L1 block height. The `update_phase` method recalculates the phase and signals transitions via `PhaseTransition`.

## Specification

### current_phase

```rust
impl EpochManager {
    pub fn current_phase(&self) -> EpochPhase {
        self.inner.read().current_epoch.phase
    }
}
```

Returns the current `EpochInfo.phase` from the manager's inner state. Uses `parking_lot::RwLock` read lock for concurrent access.

### update_phase

```rust
impl EpochManager {
    pub fn update_phase(&self, l1_height: u32) -> Option<PhaseTransition> {
        let mut inner = self.inner.write();
        let old_phase = inner.current_epoch.phase;
        let new_phase = l1_progress_phase_for_network_epoch(
            inner.genesis_l1_height,
            inner.current_epoch.epoch,
            l1_height,
        );
        if new_phase != old_phase {
            inner.current_epoch.phase = new_phase;
            Some(PhaseTransition {
                epoch: inner.current_epoch.epoch,
                from: old_phase,
                to: new_phase,
                l1_height,
            })
        } else {
            None
        }
    }
}
```

- MUST recalculate the phase using `l1_progress_phase_for_network_epoch`.
- MUST update `EpochInfo.phase` if the phase has changed.
- MUST return `Some(PhaseTransition)` if a transition occurred.
- MUST return `None` if the phase is unchanged.

## Acceptance Criteria

- [ ] `current_phase()` returns the current `EpochInfo.phase`.
- [ ] `current_phase()` acquires a read lock (concurrent reads allowed).
- [ ] `update_phase()` recalculates phase from L1 height via `l1_progress_phase_for_network_epoch`.
- [ ] `update_phase()` updates `EpochInfo.phase` when phase changes.
- [ ] `update_phase()` returns `Some(PhaseTransition)` on phase change.
- [ ] `update_phase()` returns `None` when phase is unchanged.
- [ ] `PhaseTransition` contains correct epoch, from, to, and l1_height values.

## Implementation Notes

- `current_phase()` uses a read lock, allowing concurrent phase queries.
- `update_phase()` uses a write lock since it may mutate the inner state.
- Phase calculation delegates to the stateless `l1_progress_phase_for_network_epoch` function (PHS-001).
