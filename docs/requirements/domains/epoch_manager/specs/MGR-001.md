## Summary

Defines the `EpochManager` struct and its inner state. The manager uses `parking_lot::RwLock` for interior mutability, allowing concurrent reads with exclusive writes. The inner state holds all epoch lifecycle data including the current epoch, checkpoint competition, and completed epoch history.

## Specification

### EpochManager

```rust
pub struct EpochManager {
    inner: parking_lot::RwLock<EpochManagerInner>,
}
```

### EpochManagerInner

```rust
struct EpochManagerInner {
    network_id: NetworkId,
    genesis_l1_height: u32,
    current_epoch: EpochInfo,
    competition: CheckpointCompetition,
    summaries: Vec<EpochSummary>,
}
```

| Field              | Type                      | Description                                    |
|--------------------|---------------------------|------------------------------------------------|
| `network_id`       | `NetworkId`               | Identifies the network (mainnet, testnet, etc.) |
| `genesis_l1_height`| `u32`                     | L1 block height at network genesis              |
| `current_epoch`    | `EpochInfo`               | The current epoch's full state                  |
| `competition`      | `CheckpointCompetition`   | The current epoch's checkpoint competition      |
| `summaries`        | `Vec<EpochSummary>`       | History of completed epoch summaries            |

### Concurrency Model

- `parking_lot::RwLock` is used instead of `std::sync::RwLock` for better performance and no poisoning.
- Read operations (e.g., `current_phase()`, `get_epoch_info()`) acquire a read lock, allowing concurrent access.
- Write operations (e.g., `record_block()`, `advance_epoch()`) acquire a write lock for exclusive access.

## Acceptance Criteria

- [ ] `EpochManager` wraps inner state in `parking_lot::RwLock<EpochManagerInner>`.
- [ ] `EpochManagerInner` contains `network_id` field.
- [ ] `EpochManagerInner` contains `genesis_l1_height` field of type `u32`.
- [ ] `EpochManagerInner` contains `current_epoch` field of type `EpochInfo`.
- [ ] `EpochManagerInner` contains `competition` field of type `CheckpointCompetition`.
- [ ] `EpochManagerInner` contains `summaries` field of type `Vec<EpochSummary>`.
- [ ] Concurrent reads are allowed (multiple read locks can be held simultaneously).
- [ ] Writes are exclusive (write lock blocks all other access).

## Implementation Notes

- `parking_lot::RwLock` does not poison on panic, simplifying error handling compared to `std::sync::RwLock`.
- The `EpochManager` struct provides `&self` methods that internally acquire the appropriate lock, giving the appearance of interior mutability.
- `EpochManagerInner` is private; all access goes through `EpochManager` methods.
