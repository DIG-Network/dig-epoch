## Summary

Defines the `advance_epoch` method on `EpochManager` that transitions from the current completed epoch to the next one. It enforces preconditions (Complete phase, finalized checkpoint), archives the current epoch as a summary, initializes a new epoch, and resets the competition state.

## Specification

### Function Signature

```rust
impl EpochManager {
    pub fn advance_epoch(
        &self,
        l1_height: u32,
        state_root: Bytes32,
    ) -> Result<u64, EpochError>
}
```

### Steps

1. **Verify phase is Complete.** If `current_epoch.phase != EpochPhase::Complete`, return `EpochError::EpochNotComplete`.
2. **Verify checkpoint is finalized.** If no finalized checkpoint is set on the competition, return `EpochError::NoFinalizedCheckpoint`.
3. **Archive current epoch.** Convert the current `EpochInfo` into an `EpochSummary` and append it to `summaries`.
4. **Create new EpochInfo.** Initialize `EpochInfo` for `epoch + 1` with the provided `state_root`. The new epoch starts in `BlockProduction` phase with zeroed counters.
5. **Reset competition.** Reset `CheckpointCompetition` to its initial state for the new epoch.
6. **Return new epoch number.** Return the new epoch number (`u64`).

### Error Conditions

| Condition                  | Error                              |
|----------------------------|------------------------------------|
| Phase is not `Complete`    | `EpochError::EpochNotComplete`     |
| No finalized checkpoint    | `EpochError::NoFinalizedCheckpoint`|

## Acceptance Criteria

- [ ] Returns `EpochError::EpochNotComplete` when phase is not `Complete`.
- [ ] Returns `EpochError::NoFinalizedCheckpoint` when no finalized checkpoint exists.
- [ ] Current `EpochInfo` is archived as `EpochSummary` in `summaries`.
- [ ] New `EpochInfo` is created for `epoch + 1`.
- [ ] New `EpochInfo` uses the provided `state_root`.
- [ ] New `EpochInfo` starts in `BlockProduction` phase.
- [ ] New `EpochInfo` has zeroed counters (blocks_produced, total_fees, total_transactions).
- [ ] `CheckpointCompetition` is reset.
- [ ] Returns the new epoch number (`u64`).

## Implementation Notes

- Both precondition checks MUST occur before any state mutation.
- The summary is appended to the `summaries` vec, maintaining epoch ordering (MGR-007).
- The `state_root` represents the L2 state at the epoch boundary.
- After `advance_epoch`, the manager is ready for the next epoch's `BlockProduction` phase.
