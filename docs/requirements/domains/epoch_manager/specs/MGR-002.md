## Summary

Defines the `record_block` method on `EpochManager` that records block production statistics for the current epoch. Each call increments the block count and accumulates fees and transaction counts. The method enforces that blocks can only be recorded during the `BlockProduction` phase.

## Specification

### Function Signature

```rust
impl EpochManager {
    pub fn record_block(&self, fees: u64, tx_count: u64) -> Result<()> {
        let mut inner = self.inner.write();
        if inner.current_epoch.phase != EpochPhase::BlockProduction {
            return Err(EpochError::PhaseMismatch {
                expected: EpochPhase::BlockProduction,
                got: inner.current_epoch.phase,
            });
        }
        inner.current_epoch.blocks_produced += 1;
        inner.current_epoch.total_fees += fees;
        inner.current_epoch.total_transactions += tx_count;
        Ok(())
    }
}
```

### Behavior

1. Acquires a write lock on the inner state.
2. Checks that the current phase is `BlockProduction`. If not, returns `EpochError::PhaseMismatch`.
3. Increments `blocks_produced` by 1.
4. Adds `fees` to `total_fees`.
5. Adds `tx_count` to `total_transactions`.
6. Returns `Ok(())`.

## Acceptance Criteria

- [ ] `blocks_produced` is incremented by 1 per call.
- [ ] `total_fees` is incremented by the `fees` argument.
- [ ] `total_transactions` is incremented by the `tx_count` argument.
- [ ] Returns `EpochError::PhaseMismatch` when phase is not `BlockProduction`.
- [ ] `PhaseMismatch` error contains `expected: BlockProduction` and the actual current phase.
- [ ] Multiple sequential calls accumulate correctly.

## Implementation Notes

- The method acquires a write lock because it mutates the inner state.
- Phase check MUST occur before any mutation to ensure atomicity on rejection.
- This method is the primary way block production is tracked during an epoch.
