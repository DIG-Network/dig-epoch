# CON-001: Epoch Geometry

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 2.1](../../../../resources/SPEC.md)

## Summary

Epoch geometry constants define the fundamental sizing of epochs in the DIG L2 blockchain. These three values determine how many L2 blocks fit in an epoch, how many L1 blocks span the epoch's phase window, and where the L2 chain begins. All height-epoch arithmetic, phase calculation, and reward computation derive from these constants.

## Specification

```rust
/// L2 blocks per epoch -- each epoch spans exactly this many committed heights.
/// Epoch e contains heights [e * BLOCKS_PER_EPOCH + 1, (e + 1) * BLOCKS_PER_EPOCH].
pub const BLOCKS_PER_EPOCH: u64 = 32;

/// L1 blocks per epoch window (~10 minutes at 18s Chia block time).
/// Phase progression is computed as a percentage of this window.
pub const EPOCH_L1_BLOCKS: u32 = 32;

/// First L2 block height. The genesis block is at height 1, not 0.
pub const GENESIS_HEIGHT: u64 = 1;
```

**Derivations and relationships:**

| Relationship | Expression |
|-------------|-----------|
| Epoch e L2 range | `[e * 32 + 1, (e + 1) * 32]` |
| Epoch 0 L2 range | `[1, 32]` |
| Epoch 1 L2 range | `[33, 64]` |
| Epoch duration (wall clock) | `32 blocks * 3s = 96 seconds` |
| Epoch L1 duration | `32 * 18s = ~576 seconds (~10 minutes)` |
| Height-to-epoch formula | `epoch = (height - 1) / BLOCKS_PER_EPOCH` |

## Acceptance Criteria

- `BLOCKS_PER_EPOCH` is `u64` and equals `32`
- `EPOCH_L1_BLOCKS` is `u32` and equals `32`
- `GENESIS_HEIGHT` is `u64` and equals `1`
- All three are `pub const` and accessible from the crate root
- The height-to-epoch formula `(h - 1) / 32` produces correct epoch numbers for all valid heights

## Implementation Notes

- `BLOCKS_PER_EPOCH` is `u64` because L2 heights are `u64`, and the constant participates in arithmetic with heights
- `EPOCH_L1_BLOCKS` is `u32` because L1 heights are `u32` (Chia L1 uses 32-bit heights)
- `GENESIS_HEIGHT = 1` (not 0) is a deliberate design decision (SPEC Decision #3) to avoid ambiguity with "no blocks"
- These constants are used extensively in `arithmetic.rs` and should never be hardcoded elsewhere
