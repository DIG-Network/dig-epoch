# SER-002: to_bytes and from_bytes Conventions

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 11.2](../../../../resources/SPEC.md)

## Summary

`to_bytes()` must be infallible (panics on failure, which should never occur with well-formed types). `from_bytes()` must be fallible, returning `EpochError` on invalid input. This matches the dig-block serialization convention.

## Specification

All six serializable types MUST implement `to_bytes()` and `from_bytes()` following the same infallible/fallible convention:

```rust
impl EpochInfo {
    /// Serialize to bytes. Infallible - panics on failure (should never happen).
    pub fn to_bytes(&self) -> Vec<u8> {
        bincode::serialize(self).expect("EpochInfo serialization should never fail")
    }

    /// Deserialize from bytes. Returns error on invalid data.
    pub fn from_bytes(bytes: &[u8]) -> Result<Self, EpochError> {
        bincode::deserialize(bytes)
            .map_err(|e| EpochError::InvalidData(e.to_string()))
    }
}
```

## Acceptance Criteria

- [ ] `to_bytes()` returns `Vec<u8>` (not `Result`) -- infallible
- [ ] `to_bytes()` panics via `expect()` on serialization failure
- [ ] `from_bytes()` returns `Result<Self, EpochError>` for all six types
- [ ] Invalid bytes produce `EpochError::InvalidData`
- [ ] Truncated bytes produce appropriate error
- [ ] Empty bytes produce appropriate error
- [ ] Convention matches dig-block's `to_bytes()`/`from_bytes()` pattern

## Implementation Notes

- The infallible `to_bytes()` convention is safe because bincode serialization of well-formed Rust structs with serde should never fail. The `expect()` message documents this invariant and names the type for diagnostics.
- `from_bytes()` must handle all categories of invalid input: truncated data, corrupted data, extra trailing bytes (depending on bincode configuration), and type mismatches.
- All six types use `EpochError::InvalidData` as the error variant, unlike dig-block which splits between `BlockError::InvalidData` and `CheckpointError::InvalidData`. This simplification is possible because dig-epoch has a unified error type.
