# SER-001: Bincode Serialization for All Types

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 11.1](../../../../resources/SPEC.md)

## Summary

All epoch types must use bincode for serialization. Bincode produces compact binary output with no schema overhead, making it efficient for network transmission and storage. This matches the serialization approach used by dig-block.

## Specification

All six serializable epoch types MUST derive `Serialize` and `Deserialize` and use bincode as the exclusive serialization format:

```rust
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize)]
pub struct EpochInfo { /* ... */ }

#[derive(Serialize, Deserialize)]
pub struct EpochSummary { /* ... */ }

#[derive(Serialize, Deserialize)]
pub struct DfspCloseSnapshot { /* ... */ }

#[derive(Serialize, Deserialize)]
pub struct CheckpointCompetition { /* ... */ }

#[derive(Serialize, Deserialize)]
pub struct RewardDistribution { /* ... */ }

#[derive(Serialize, Deserialize)]
pub struct EpochCheckpointData { /* ... */ }

// Bincode is used exclusively for wire/storage format
impl EpochInfo {
    pub fn to_bytes(&self) -> Vec<u8> {
        bincode::serialize(self).expect("serialization should never fail")
    }

    pub fn from_bytes(bytes: &[u8]) -> Result<Self, EpochError> {
        bincode::deserialize(bytes)
            .map_err(|e| EpochError::InvalidData(e.to_string()))
    }
}

// Same pattern for EpochSummary, DfspCloseSnapshot, CheckpointCompetition,
// RewardDistribution, EpochCheckpointData
```

## Acceptance Criteria

- [ ] `EpochInfo` uses bincode for serialization
- [ ] `EpochSummary` uses bincode for serialization
- [ ] `DfspCloseSnapshot` uses bincode for serialization
- [ ] `CheckpointCompetition` uses bincode for serialization
- [ ] `RewardDistribution` uses bincode for serialization
- [ ] `EpochCheckpointData` uses bincode for serialization
- [ ] No other serialization format (JSON, MessagePack, etc.) is used for wire/storage
- [ ] All six types derive `serde::Serialize` and `serde::Deserialize`

## Implementation Notes

- Bincode's default configuration uses little-endian byte order and variable-length integer encoding, consistent with dig-block. If fixed configuration is needed for cross-platform compatibility, use `bincode::options()` to set explicit options.
- JSON serialization may be provided separately for debugging/logging but MUST NOT be used for consensus-critical serialization.
- The six types listed here are the serializable subset of all epoch types. Types like `EpochPhase`, `EpochEvent`, and `PhaseTransition` may also derive Serialize/Deserialize but do not require `to_bytes()`/`from_bytes()` methods.
