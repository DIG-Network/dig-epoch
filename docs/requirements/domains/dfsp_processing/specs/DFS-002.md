# DFS-002: Storage Proof and Issuance

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 9.3](../../../../resources/SPEC.md)

## Summary

Storage proof evaluation determines which nodes submitted valid proofs during the epoch, and the issuance preview distributes the epoch's total issuance pool proportionally based on proof shares. This is central to the DFSP incentive mechanism -- nodes are rewarded for proving they store data.

## Specification

DfspEpochStorageProofEvaluationContextV1 MUST be defined as:

```rust
pub struct DfspEpochStorageProofEvaluationContextV1 {
    pub evaluated_epoch: u64,
    pub proved_node_ids: Vec<Bytes32>,
}
```

DfspEpochIssuancePreviewV1 MUST be defined as:

```rust
pub struct DfspEpochIssuancePreviewV1 {
    /// Per-node proof share counts.
    pub proof_shares_by_node: Vec<(Bytes32, u64)>,
    /// Sum of all proof shares.
    pub total_proof_shares: u64,
    /// Total issuance pool available this epoch (mojos).
    pub epoch_total_issuance_pool_mojos: u128,
    /// Per-node issuance allocation (mojos).
    pub node_issuance_mojos: Vec<(Bytes32, u128)>,
}
```

Key rules:
- DfspEpochStorageProofEvaluationContextV1 records the epoch and the set of node IDs that submitted valid storage proofs
- proved_node_ids contains only nodes with validated proofs (invalid or missing proofs are excluded)
- DfspEpochIssuancePreviewV1 maps each node to its proof-weighted share, records the total pool and total shares, and computes per-node issuance allocations
- `total_proof_shares` MUST equal the sum of all individual proof shares in `proof_shares_by_node`
- `epoch_total_issuance_pool_mojos` is `u128` to match DFSP issuance precision
- `node_issuance_mojos` contains the computed per-node issuance in mojos (u128)
- The sum of all `node_issuance_mojos` values MUST not exceed `epoch_total_issuance_pool_mojos`
- Nodes not present in proof_shares_by_node receive zero issuance

## Acceptance Criteria

- [ ] DfspEpochStorageProofEvaluationContextV1 contains evaluated_epoch (u64) and proved_node_ids (Vec<Bytes32>)
- [ ] DfspEpochIssuancePreviewV1 contains proof_shares_by_node (Vec<(Bytes32, u64)>), total_proof_shares (u64), epoch_total_issuance_pool_mojos (u128), and node_issuance_mojos (Vec<(Bytes32, u128)>)
- [ ] proved_node_ids only contains nodes with valid storage proofs
- [ ] total_proof_shares equals the sum of all individual proof shares
- [ ] Issuance is distributed proportionally based on proof shares
- [ ] Sum of node_issuance_mojos does not exceed epoch_total_issuance_pool_mojos
- [ ] Nodes without proofs receive zero issuance
- [ ] All fields are publicly accessible

## Implementation Notes

- Storage proofs are evaluated during the Proofs stage of the 7-stage pipeline (DFS-003)
- The issuance pool size is determined by the reward economics domain (reward_economics)
- proof_shares_by_node uses Bytes32 node IDs as keys, consistent with the node registry
- The issuance preview is consumed by DFS-003 (Boundary Finalize) and DFS-004 (operations digest)
- HashMap ordering does not affect determinism because the operations digest (DFS-004) uses sorted iteration
