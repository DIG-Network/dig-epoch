# DFS-007: Parse Burn Policy Schedule

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 9.2](../../../../resources/SPEC.md)

## Summary

`parse_dfsp_epoch_burn_policy_schedule_v1` parses a burn policy schedule from a string configuration into a vector of `DfspEpochBurnPolicyScheduleEntryV1`. This enables protocol governance to define height-activated burn parameter overrides via configuration strings rather than code changes.

## Specification

```rust
/// Parses a burn policy schedule from a string configuration.
///
/// Each entry in the schedule defines an activation height and the burn policy
/// parameters that take effect from that height onward. The parsed schedule is
/// used by resolve_dfsp_epoch_burn_policy_from_schedule() (DFS-001) to determine
/// the active burn policy at any given height.
///
/// Returns an error if the schedule string is malformed.
pub fn parse_dfsp_epoch_burn_policy_schedule_v1(
    schedule_str: &str,
) -> Result<Vec<DfspEpochBurnPolicyScheduleEntryV1>, EpochError>
```

Key rules:
- MUST parse the input string into a vector of `DfspEpochBurnPolicyScheduleEntryV1`
- Each entry MUST contain a `start_height: u64` and a `policy: DfspEpochBurnPolicyV1`
- MUST return `Err(EpochError)` if the input string is malformed or contains invalid values
- The returned vector SHOULD be sorted by `start_height` in ascending order
- An empty schedule string MUST return an empty vector (not an error)

## Acceptance Criteria

- [ ] Parses valid schedule string into `Vec<DfspEpochBurnPolicyScheduleEntryV1>`
- [ ] Returns error for malformed input
- [ ] Returns empty vector for empty input string
- [ ] Each parsed entry contains correct `start_height` and `policy` values
- [ ] Parsed `policy.min_bond_threshold` is `u128`
- [ ] Parsed `policy.wall_clock_epoch_seconds` is `u64`

## Implementation Notes

- This function is the counterpart to `resolve_dfsp_epoch_burn_policy_from_schedule()` (DFS-001) -- it produces the schedule that `resolve` consumes
- `DfspEpochBurnPolicyScheduleEntryV1` is defined in SPEC Section 3.14.4
- The exact string format is implementation-defined but should be deterministic and human-readable
- This supports runtime configuration of burn policy evolution without code changes
