## Summary

The burn policy governs how inactive or under-bonded storage nodes are penalized at epoch boundaries. DfspEpochBurnPolicyV1 defines the protocol parameters, DfspEpochBurnContextV1 captures the resolved context for a specific node evaluation, and helper functions provide default and schedule-based policy resolution.

## Specification

Key rules:
- DfspEpochBurnPolicyV1 defines protocol-level parameters that control burn behavior
- DfspEpochBurnContextV1 captures the evaluation context for a specific node at a specific epoch boundary

## Acceptance Criteria

- [ ] DfspEpochBurnPolicyV1 contains min_bond_threshold (u128) and wall_clock_epoch_seconds (u64)
- [ ] DfspEpochBurnContextV1 contains elapsed_wall_clock_epochs (u64) and min_bond_threshold (u128)
- [ ] protocol_dfsp_epoch_burn_policy() returns a valid default policy
- [ ] resolve_dfsp_epoch_burn_policy_from_schedule() returns correct policy for heights before, at, and after schedule entries
- [ ] resolve_dfsp_epoch_burn_policy_from_schedule() falls back to default when no schedule entry matches
- [ ] All fields are publicly accessible

## Implementation Notes

- **Type aliases:** `NodeId = Bytes32` (node identifiers). `Cid` references come from external crates.
- The burn policy is the first stage (EpochBurn) in the 7-stage DFSP epoch-boundary pipeline
- `min_bond_threshold` is `u128` to match DFSP mojo precision used throughout the DFSP subsystem
- min_bond_threshold determines the minimum collateral a node must maintain to avoid being burned
- wall_clock_epoch_seconds is used to compute elapsed_wall_clock_epochs for inactivity detection
- The height-based schedule allows protocol upgrades to adjust burn parameters without code changes
- This is evaluated during DFS-003 (Boundary Finalize) as part of the deterministic pipeline
