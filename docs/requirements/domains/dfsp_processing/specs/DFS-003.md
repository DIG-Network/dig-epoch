# DFS-003: Boundary Finalize and Staged Outputs

> **Authoritative requirement:** [NORMATIVE.md](../NORMATIVE.md)
> **Verification:** [VERIFICATION.md](../VERIFICATION.md)
> **Tracking:** [TRACKING.yaml](../TRACKING.yaml)
> **Spec reference:** [SPEC.md - Section 9.1](../../../../resources/SPEC.md)

## Summary

The DFSP epoch-boundary pipeline is a 7-stage deterministic process that finalizes all DFSP state transitions at the end of an epoch. DfspEpochBoundaryFinalizePreviewV1 captures the finalization plan, DfspEpochBoundaryStagedOutputsV1 collects all intermediate outputs, and DfspExecutionStageV1 enumerates the pipeline stages.

## Specification

DfspEpochBoundaryFinalizePreviewV1 MUST be defined as:

```rust
pub struct DfspEpochBoundaryFinalizePreviewV1 {
    /// The epoch being finalized.
    pub evaluated_epoch: u64,
    /// Fragment reassignment batch plan.
    pub reassignment_batch_plan: DfspEpochReassignmentBatchPlanPreviewV1,
    /// Issuance preview from proof evaluation.
    pub issuance_preview: DfspEpochIssuancePreviewV1,
    /// SHA-256 digest of all staged operations.
    pub operations_digest: Bytes32,
}
```

DfspEpochBoundaryStagedOutputsV1 MUST contain all intermediate outputs from the 7-stage pipeline:

```rust
pub struct DfspEpochBoundaryStagedOutputsV1 {
    /// The epoch being processed.
    pub evaluated_epoch: u64,
    /// Fragment CIDs considered during reassignment.
    pub fragment_cids_considered: Vec<Cid>,
    /// Fragment CIDs actually reassigned.
    pub reassigned_fragments: Vec<Cid>,
    /// Reassignment batch plan.
    pub reassignment_batch_plan: DfspEpochReassignmentBatchPlanPreviewV1,
    /// Issuance preview.
    pub issuance_preview: DfspEpochIssuancePreviewV1,
    /// Finalize preview.
    pub finalize_preview: DfspEpochBoundaryFinalizePreviewV1,
}
```

DfspExecutionStageV1 MUST define the following enum:

```rust
pub enum DfspExecutionStageV1 {
    EpochBurn,
    CollateralAndCid,
    NodeRegistry,
    Proofs,
    Namespace,
    FinalizeRoots,
}
```

Key rules:
- The 7-stage pipeline MUST execute in the fixed order defined by DfspExecutionStageV1
- Each stage MUST be deterministic: given the same inputs, it produces identical outputs
- DfspEpochBoundaryStagedOutputsV1 MUST capture outputs from every stage for auditability
- DfspEpochBoundaryFinalizePreviewV1 contains the finalization plan produced after all stages complete
- operations_digest MUST be computed over the reassignment_batch_plan and issuance_preview (see DFS-004)

## Acceptance Criteria

- [ ] DfspEpochBoundaryFinalizePreviewV1 contains evaluated_epoch (u64), reassignment_batch_plan, issuance_preview, and operations_digest
- [ ] DfspEpochBoundaryStagedOutputsV1 contains all 6 fields: evaluated_epoch, fragment_cids_considered, reassigned_fragments, reassignment_batch_plan, issuance_preview, finalize_preview
- [ ] DfspExecutionStageV1 defines exactly 6 variants: EpochBurn, CollateralAndCid, NodeRegistry, Proofs, Namespace, FinalizeRoots
- [ ] Pipeline stages execute in fixed order
- [ ] Pipeline is deterministic: same inputs produce identical staged outputs
- [ ] All fields are publicly accessible

## Implementation Notes

- The "7-stage" pipeline uses 6 named execution stages (DfspExecutionStageV1) plus a final aggregation step that produces the DfspEpochBoundaryFinalizePreviewV1
- EpochBurn: burns expired bonds and removes inactive nodes (uses DFS-001 burn policy)
- CollateralAndCid: processes collateral adjustments and CID lifecycle transitions
- NodeRegistry: updates the node registry SMT with registrations and deregistrations
- Proofs: evaluates storage proofs and computes issuance shares (uses DFS-002)
- Namespace: processes namespace updates and computes namespace rollup (uses DFS-006)
- FinalizeRoots: computes final DFSP roots and commitment digest (uses DFS-004)
- Determinism is critical because all validators must independently arrive at the same result
