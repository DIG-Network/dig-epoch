## Summary

`apply_epoch_storage_proof_evaluation_step_v1` is the Stage 5 (Proofs) step in the DFSP epoch-boundary pipeline. It evaluates storage proofs submitted during the epoch, determines which nodes provided valid retrieval proofs, computes their proof shares, and produces a `DfspEpochIssuancePreviewV1` that distributes the epoch's issuance pool proportionally.

## Specification

```rust
/// Evaluates storage proofs submitted during the epoch.
/// Determines which nodes provided valid retrieval proofs
/// and computes their proof shares for issuance allocation.
///
/// This is Stage 5 (Proofs) of the 7-stage DFSP epoch-boundary pipeline.
/// It reads the DfspEpochStorageProofEvaluationContextV1 (which contains the
/// evaluated epoch and the list of proved node IDs) along with additional
/// DFSP state inputs, and produces a DfspEpochIssuancePreviewV1 containing
/// per-node proof shares and issuance allocations.
pub fn apply_epoch_storage_proof_evaluation_step_v1(
    context: &DfspEpochStorageProofEvaluationContextV1,
    // ... additional DFSP state inputs
) -> DfspEpochIssuancePreviewV1
```

Key rules:
- MUST evaluate all proved node IDs from the context
- MUST compute proof shares proportionally for each node
- MUST distribute `epoch_total_issuance_pool_mojos` proportionally based on proof shares
- Nodes not present in `proved_node_ids` MUST receive zero issuance
- The sum of all `node_issuance_mojos` MUST not exceed `epoch_total_issuance_pool_mojos`
- MUST be deterministic: given the same inputs, produces identical output

## Acceptance Criteria

- [ ] Accepts a `DfspEpochStorageProofEvaluationContextV1` and produces a `DfspEpochIssuancePreviewV1`
- [ ] Distributes issuance proportionally based on proof shares
- [ ] Nodes without proofs receive zero issuance
- [ ] Total distributed issuance does not exceed the issuance pool
- [ ] Function is deterministic (same inputs produce identical output)
- [ ] `total_proof_shares` equals the sum of all individual proof shares

## Implementation Notes

- This function is called during the Proofs stage (Stage 5) of the pipeline (DFS-003)
- The evaluation context is built from storage proofs collected during the epoch's block production phase
- The issuance pool size is determined by the reward economics domain
- The exact additional DFSP state inputs will be defined during implementation (e.g., node weights, CID assignments)
- This is a pure function with no side effects -- all inputs are immutable references
